# GGSEL SELLER

Telegram-бот для продавцов GGsel: уведомления о заказах и сообщениях, ответы покупателям, команды с готовым текстом и управление настройками из одной группы.

Каждая переписка открывается в отдельной теме Telegram. Вы пишете ответ в этой теме — бот передаёт его покупателю в GGsel. Управление доступно через `/menu`, без отдельного веб-интерфейса.

Проект поддерживает один аккаунт продавца и одну Telegram-группу на экземпляр. Это независимый инструмент, не официальный продукт GGsel.

## Возможности

| Раздел | Что умеет |
| --- | --- |
| 💬 Чаты и ответы | Обнаруживает переписки через API независимо от списка последних продаж; создаёт темы и передаёт текстовые ответы |
| 🔔 Уведомления | Показывает сообщения покупателей, новые заказы и отзывы |
| ⌨️ Команды покупателей | Отвечает заданным текстом на `!инструкция`, `/help` и другие команды или фразы |
| ⚙️ Автоответы | Настраивает приветствия, ответы на отзывы и правила по параметрам заказа |
| 🗂 Конфигурация | Экспортирует настройки в JSON; импортирует с предпросмотром, подтверждением и резервной копией |
| 🧩 Плагины | Подключает собственные Python-обработчики команд покупателей |
| 🩺 Состояние | Показывает последние успешные проверки API и очереди; позволяет остановить и возобновить синхронизацию |
| 💰 Кошелёк и статистика | Показывает баланс продавца и статистику обработки |

Переписка и состояние доставки сохраняются в SQLite. Сообщения продавца и загруженная история не запускают автоответы. Доступ операторов ограничивается списком Telegram ID.

## Быстрый запуск с Docker

Потребуются Linux-сервер с Git, Docker Engine и Docker Compose, аккаунт продавца GGsel с доступом к Seller API, а также Telegram-бот и группа с темами.

### 1. Подготовьте GGsel и Telegram

1. В кабинете GGsel создайте API-ключ и узнайте числовой ID продавца. Если для API включён список разрешённых IP, добавьте внешний IP сервера.
2. Создайте бота через [@BotFather](https://t.me/BotFather) и сохраните его токен.
3. Создайте отдельную закрытую группу Telegram, включите **Темы** и добавьте бота.
4. Назначьте бота администратором с правами отправки сообщений, управления темами и удаления сообщений.
5. Узнайте ID группы и личные числовые Telegram ID операторов. ID группы обычно начинается с `-100`.

В группу будут поступать переписки и сведения о заказах. Добавляйте в неё только операторов магазина.

### 2. Скачайте и настройте проект

```bash
git clone https://github.com/Sereza111/GGSEL_SELLER.git
cd GGSEL_SELLER
cp .env.example .env
chmod 600 .env
nano .env
```

Заполните обязательные переменные своими значениями:

| Переменная | Значение |
| --- | --- |
| `GGSEL_SELLER_ID` | Числовой ID продавца GGsel |
| `GGSEL_API_KEY` | Ключ из кабинета продавца |
| `TELEGRAM_BOT_TOKEN` | Токен созданного бота |
| `TELEGRAM_GROUP_ID` | ID группы с темами |
| `TELEGRAM_ALLOWED_USER_IDS` | Личные Telegram ID разрешённых операторов через запятую |

Членство в группе и права администратора сами по себе не разрешают управление ботом. Если список операторов пуст, команды и ответы будут заблокированы. После запуска `/id` или `/myid` в настроенной группе показывает ID отправителя; затем можно дополнить `.env` и пересоздать контейнер.

Полный шаблон параметров находится в [.env.example](.env.example). Не добавляйте заполненный `.env` в Git и не прикладывайте его к публичным обращениям.

### 3. Запустите бота

```bash
docker compose up -d --build
docker compose logs --tail=100 -f ggsel-bot
```

Отправьте `/menu` в группе. При первом запуске автоматические сообщения покупателям выключены: сначала задайте свои тексты и правила, затем включите нужные функции. При перезапуске существующие настройки сохраняются.

Бот сам опрашивает GGsel и Telegram. Для этой установки не нужны входящие порты, домен или URL кастомных уведомлений GGsel.

После изменения `.env` примените настройки:

```bash
docker compose up -d --force-recreate
```

### Запуск без Docker

Для запуска напрямую используйте Linux и Python 3.12. Из каталога проекта:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

Создайте и заполните `.env` по шагу 2 выше. В шаблоне уже указаны локальные пути к базе, настройкам и плагинам в `data/`. Запускайте через входной скрипт: он создаёт начальное состояние с выключенными автоответами.

```bash
python container_entrypoint.py python main.py
```

Скрипт `python setup.py` также умеет запросить ключи и Telegram ID интерактивно. После его использования проверьте дополнительные параметры по `.env.example`. Для постоянной работы на сервере используйте менеджер процессов; в Docker Compose перезапуск уже настроен.

## Как пользоваться

### Ответ покупателю

Откройте **«Чаты и ответы»**, выберите покупателя и напишите обычный текст в его теме. Реакция 🔥 означает, что API GGsel принял отправку. Если отправка не подтверждена, бот покажет ошибку; перед повтором проверьте историю диалога.

Текст в общей теме не отправляется покупателям. Во время настройки команды или автоответа ввод обрабатывается редактором, даже если настройка открыта внутри темы покупателя. `/cancel` отменяет ввод, `/menu` возвращает к управлению.

### Команды покупателей

Например, чтобы выдавать инструкцию по команде:

1. Откройте `/menu` → **«Команды покупателей»** → **«Добавить»**.
2. Отправьте `!инструкция`.
3. Отправьте текст инструкции.
4. Убедитесь, что правило и общий переключатель в **«Автоответы»** включены.

Покупатель пишет `!инструкция` в **чате GGsel** и получает заданный текст. Команды, начинающиеся с `!` или `/`, создаются с точным совпадением; регистр не учитывается. В карточке правила можно изменить фразу, ответ и режим совпадения.

### Уведомления и остановка синхронизации

В **«Уведомления»** переключается доставка новых сообщений в темы. Пропущенные при выключенном переключателе сообщения не догружаются автоматически; историю можно открыть командой `/history`. Уведомления о заказах и отзывах обрабатываются отдельно при включённой синхронизации.

В **«Состояние»** можно остановить обмен с GGsel. Пока синхронизация приостановлена, бот не обрабатывает новые события и не отправляет ответы покупателям; меню Telegram остаётся доступным.

### Конфигурация

**«Конфигурация» → «Скачать JSON»** сохраняет тексты автоответов и переключатель уведомлений. Экспорт не содержит ключей доступа и истории переписок.

Для восстановления выберите **«Загрузить JSON»**, отправьте файл в ту же тему, проверьте предпросмотр и нажмите **«Применить настройки»**. Импорт заменяет настройки; предыдущий файл сохраняется на сервере. Максимальный размер — 256 КиБ. Экспорт настроек не заменяет резервную копию базы данных.

### Плагины

Собственные плагины устанавливаются файлами на сервере и включаются в разделе **«Плагины»**. Для обычного ответа текстом на команду плагин не требуется.

Интерфейс, установка и пример: [PLUGINS.md](PLUGINS.md). Плагины FunPay Cardinal требуют адаптации и напрямую не поддерживаются.

## Команды Telegram

| Команда | Действие |
| --- | --- |
| `/menu`, `/start` | Открыть управление |
| `/help` | Показать справку |
| `/id`, `/myid` | Показать личный Telegram ID в настроенной группе |
| `/history` | Повторно показать историю в теме покупателя |
| `/options` | Показать параметры заказа в его теме |
| `/review` | Показать отзыв по заказу в его теме |
| `/cancel` | Отменить ввод настройки |
| `/stop_sync` | Приостановить обмен с GGsel |
| `/start_sync` | Возобновить обмен с GGsel |

Во время ввода фразы для автоответа `/help` может быть самой командой покупателя. Для выхода из редактора используйте `/cancel`.

## Хранение данных и обновление

Docker Compose сохраняет базу SQLite, настройки, журнал и установленные плагины в постоянном томе, подключённом как `/data`. Пересоздание контейнера не удаляет этот том. Команда `docker compose down -v` удаляет его вместе с данными — для обычного обновления она не нужна.

Перед обновлением сохраните копию состояния. Пример для Bash из каталога проекта:

```bash
mkdir -p backups
backup_dir="./backups/$(date -u +%Y%m%d-%H%M%S)"
docker compose stop ggsel-bot
docker compose cp ggsel-bot:/data "$backup_dir"
cp .env "$backup_dir.env"
chmod 600 "$backup_dir.env"
docker compose start ggsel-bot
```

Храните копии вне публичного репозитория. Чтобы восстановить состояние, остановите бота и верните сохранённые файлы в его `/data`; запускайте совместимую с этой базой версию приложения.

Обновление исходников и контейнера:

```bash
git pull --ff-only
docker compose up -d --build
docker compose logs --tail=100 ggsel-bot
```

Автоматическое обновление отключено в стандартной установке. Для Docker используйте пересборку контейнера.

## Ограничения и диагностика

- Пересылка ответов покупателю поддерживает **текст**. Для файлов используйте кабинет GGsel.
- Новые события поступают с задержкой опроса API. Пустой список тем до появления действительных чатов или заказов не означает сбой.
- При первоначальном импорте старая история не запускает ответы на прошлые команды. Неизвестный или неоднозначный отправитель также не запускает автоответ.
- Бот зависит от доступности и разрешений Seller API. Документация: [GGsel Seller API](https://seller.ggsel.com/docs).

| Проблема | Что проверить |
| --- | --- |
| `/menu` не отвечает | ID группы и оператора в `.env`, токен, журнал контейнера |
| Темы не создаются | Включены ли темы, есть ли у бота право управлять ими, видны ли действительные переписки в API |
| Сообщения видны, но телефон молчит | Звук и уведомления самой группы и отдельных тем в Telegram |
| Ответ не уходит в GGsel | Синхронизация включена, выбрана тема покупателя, ключ API действителен |
| Команда покупателя не срабатывает | Правило включено, включены автоответы, текст соответствует режиму совпадения |

При обращении в [Issues](https://github.com/Sereza111/GGSEL_SELLER/issues) укажите версию, шаги воспроизведения и очищенный фрагмент журнала. Уберите токены, ключи, адреса покупателей и содержимое личных переписок.

## Разработка и тесты

Основная среда — Linux и Python 3.12. Установка зависимостей и запуск тестов:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -p 'test_*.py' -v
```

Тесты проверяют маршрутизацию ответов, фильтрацию отправителя, сохранение состояния, обработку повторов, редактор команд, импорт настроек и выполнение плагинов. Для проверок доставки используются подменённые транспорты, без сообщений реальным покупателям.
